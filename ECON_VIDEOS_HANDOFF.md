# Economics Explainer Videos — Project Handoff

Compiled from a cloud session to continue locally. Covers: the content plan, the
working setup (Manim + Remotion + voiceover), every gotcha hit along the way, and
the exact commands to reproduce it.

---

## 1. The goal

Short (~1–2 min) animated economics explainer videos, teaching-channel style, for
curriculum-aligned microeconomics topics (AP/IB/intro college econ). Two rendering
tracks were built in parallel:

- **Manim** (Python) — for graph-driven content: supply/demand curves, shifting
  curves, shaded areas, camera pans/zooms into a region while narrating it. This
  is the stronger fit for this niche and where most future work should go.
- **Remotion** (React/TypeScript, renders via headless Chromium) — for
  UI/motion-graphics-style content (game theory payoff matrices, data-driven
  dashboards). Weaker fit for curve-heavy econ content; kept as a secondary option.

A synthetic voiceover pipeline (no recording) is wired into the Manim track via
`manim-voiceover`, with two swappable backends: **Piper** (free, offline, for
unlimited iteration) and **ElevenLabs** (paid, for the final polished render).

## 2. Content roadmap (priority order)

The tax + deadweight-loss video (`tax_dwl_camera_voiceover.py`) is the **template**.
Almost every intro-micro topic is "shift a curve → find the new intersection →
shade a region → zoom in and explain it" — the exact same code shape. Reuse it
rather than rebuilding from scratch each time.

1. **Price ceilings & floors** (rent control, minimum wage) — shortage/surplus
   shading, closest reuse of the existing engine.
2. **Subsidies** — mirror image of a tax (curve shifts down instead of up).
   Near-zero new code.
3. **Externalities** — negative (pollution: MSC vs MPC, Pigouvian tax) and
   positive (education: MSB vs MPB, subsidy). One extra curve, same engine.
4. **Elasticity's effect on tax incidence / DWL size** — good candidate for a
   split-screen or side-by-side camera comparison (steep vs flat curves).
5. **Monopoly deadweight loss** (MR = MC vs competitive outcome) — still
   graph-shifting, new curve types (MR, MC, ATC).

**Deliberately deferred:** macro topics (AD-AS, Phillips curve, IS-LM). Real
demand, but they need a different multi-curve engine — don't dilute the reuse
advantage of the micro series until it's proven out.

## 4. Local environment setup

### 4a. Manim + manim-voiceover + Piper

```bash
cd manim-demo

# Use a venv — installing manim-voiceover's dependencies (esp. the `srt` package)
# directly with system pip hits a Debian/Ubuntu patched-distutils bug
# ("AttributeError: install_layout") on some systems. A clean venv avoids it.
python3 -m venv venv
./venv/bin/pip install --upgrade pip setuptools wheel
./venv/bin/pip install manim manim-voiceover piper-tts "elevenlabs<0.3,>=0.2.27"

# System dependencies Manim needs (Debian/Ubuntu; adjust for your OS):
sudo apt-get install -y ffmpeg libpango1.0-dev pkg-config sox libsox-fmt-mp3
```

**Why `libpango1.0-dev` specifically, not just `libpango-1.0-0`:** Manim's
`manimpango` dependency needs pkg-config to find `pangocairo.pc` at build time.
The runtime library package doesn't ship that `.pc` file — only the `-dev`
package does. Symptom if missing: `RequiredDependencyException: pangocairo >=
1.30.0 is required` during `pip install manim`, even though pango is "installed."

**Why `sox`:** `manim-voiceover` shells out to SoX for audio processing. Without
it, you'll see a `WARNING SoX could not be found!` and voiceover features break.

Voice model: already included in `voices/`. To get others or verify freshness,
use Piper's own downloader (this pulls from Hugging Face, which should be
unrestricted on your local network — it was only blocked by the cloud sandbox's
egress policy, not a general restriction):
```bash
./venv/bin/python -m piper.download_voices en_US-lessac-medium --download-dir voices/
# Or browse available voices at https://huggingface.co/rhasspy/piper-voices
```
Consider trying a **"high" quality tier** voice locally (e.g.
`en_US-lessac-high` or `en_US-ryan-high`) — noticeably better than the
"medium" tier voice used so far, and only reachable from the cloud sandbox via a
workaround that isn't needed on an unrestricted local connection.

cd remotion-demo

## 5. How to render

### Manim (development — free, unlimited, uses Piper)
```bash
cd manim-demo
./venv/bin/manim -ql tax_dwl_camera_voiceover.py TaxDWLCameraVoiceover   # fast draft, 480p15
./venv/bin/manim -qm tax_dwl_camera_voiceover.py TaxDWLCameraVoiceover   # 720p30
./venv/bin/manim -qh tax_dwl_camera_voiceover.py TaxDWLCameraVoiceover   # 1080p60, final
```
Output lands in `media/videos/tax_dwl_camera_voiceover/<quality>/TaxDWLCameraVoiceover.mp4`,
alongside an auto-generated `.srt` subtitle file.

### Manim (final render — uses ElevenLabs, costs credits)
```bash
cd manim-demo
TTS_SERVICE=elevenlabs ELEVEN_API_KEY=<your_key> ./venv/bin/manim -qh \
  tax_dwl_camera_voiceover.py TaxDWLCameraVoiceover
```
`TTS_SERVICE` defaults to `piper` if unset — the ElevenLabs branch only
activates when you explicitly set it. Optionally set `ELEVEN_VOICE_NAME` to pick
a specific voice from your account; otherwise it uses your account's default.

**Cost control, built in:**
- Piper is called for every dev iteration; it never touches ElevenLabs credits.
- `manim-voiceover` caches generated audio **per exact sentence** (hashed, stored
  under `media/voiceovers/`). Re-rendering after tweaking only visuals (not
  narration text) does **not** re-call ElevenLabs — only lines you actually
  edited get re-synthesized and re-billed.
- **Revoke/rotate any ElevenLabs key that was ever pasted into a chat.** Store
  new keys as environment variables, not in conversation text.

### Remotion
```bash
cd remotion-demo
npx remotion render src/index.tsx TaxDWL out/tax_dwl.mp4
```

## 6. Key gotchas learned (save yourself the debugging time)

**Manim `Text()` is wider than intuition suggests.** Roughly ~0.3 scene-units
per character at a given font_size (not ~0.1, which is the natural first guess).
When placing labels inside a zoomed `MovingCameraScene` frame, budget camera
width generously or the text clips off both edges — happened twice while
building the wedge zoom-in shot.

**A `Write()` animation mid-frame is not a bug.** Manim's `Write()` strokes each
glyph's outline before filling it. A frame grabbed mid-animation shows a
half-outlined "ghost" letter — normal, resolves within a few frames, not a
rendering error.

**Camera pan/zoom recipe** (`MovingCameraScene`):
```python
self.camera.frame.save_state()                                    # once, at the top
self.play(self.camera.frame.animate.move_to(point).set(width=W))  # zoom in
self.play(Restore(self.camera.frame))                              # zoom back out
```

**H264 requires even width/height.** Remotion refuses to render odd pixel
dimensions (e.g. `height={853}` fails; `height={852}` works) — the encoder can't
handle odd numbers for this codec.

**Remotion entry files need `registerRoot()`.** A `<Composition>`-only file
without a `registerRoot(RemotionRoot)` call fails with "does not contain
registerRoot." Multiple `<Composition>` siblings need a `<>...</>` fragment
wrapper.

**Remotion + newer Chrome/Chromium: old headless mode is gone.** If your system
Chromium is recent, Remotion's default launch flags fail with "Old Headless
mode has been removed from the Chrome binary." Fix: `npx remotion browser
ensure` downloads a matching `chrome-headless-shell` Remotion knows how to
drive — do this once per machine before the first render.

**`manim-voiceover`'s `ElevenLabsService` needs the OLD `elevenlabs` SDK**
(`elevenlabs<0.3,>=0.2.27`, using top-level `generate()`/`voices()`/`save()`
functions) — not the current v1+ client-based SDK. Installing the latest
`elevenlabs` package breaks it; pin the version as shown in §4a.

**No built-in Piper backend in `manim-voiceover`.** Had to write a small custom
`SpeechService` subclass (`piper_service.py`, ~40 lines) implementing
`generate_from_text()`. Keep this file — it's the only non-obvious integration
code in the whole pipeline.

## 7. Design decisions worth keeping

- **Economic model used throughout:** Demand `P = 100 − Q`, Supply `P = 10 + Q`
  (pre-tax equilibrium Q=45, P=$55), $20/unit tax (post-tax Q=35, buyers pay $65,
  sellers keep $45 → tax revenue $700, deadweight loss $100). Clean round
  numbers, easy to sanity-check on screen and verbally.
- **Voice:** Piper `en_US-lessac-medium` for drafts. Swap to a "high" tier voice
  or ElevenLabs for final output (see §4a, §5).
- **Fonts/labels:** plain `Text()`, not `MathTex()` — this environment had no
  LaTeX installed. If your local machine has a LaTeX distribution, `MathTex` is
  available and would render true math typesetting (e.g. `e^{i\pi}+1=0`) instead
  of the ASCII approximations used here.
